# Схема — контракт между моделью и кодом

Две схемы, по одной на каждый вызов модели. Обе — JSON Schema (draft 2020-12).

| Файл | Стадия | Что описывает |
|---|---|---|
| `triage.schema.json` | 0 — отсев | метка: парковочный знак / другой знак / не знак |
| `sign.schema.json` | 1 — извлечение | структура знака: основной знак и панели под ним |
| `testset/expected/` | — | эталонная разметка всех снимков набора |

## Главное свойство: список закрыт

`additionalProperties: false` стоит на каждом объекте. Модель заполняет **только**
перечисленные поля; всё, чему в схеме места нет, отбраковывается валидацией, а не
просачивается в движок.

Единственная отдушина — `notes`: свободный текст, который в вычисления и в формулу
уверенности **не входит**. Он существует, чтобы наблюдение, для которого нет поля, было
видно при разборе ошибок, а не терялось молча. Проверка модели показала, что без такого
поля модель пишет важное в проду и оно пропадает.

## Два слоя по каждой панели

- `lines` — **дословный** шведский текст построчно, со скобками и дефисами как на знаке;
- `parsed` — то, что модель отнесла к известным категориям.

Смысл присваивает **код**: ворота это, пометка или правило — определяется по справочнику
`reference/signs/`, а не моделью. Поле `schema:` в каждой записи справочника показывает,
какому полю схемы запись соответствует.

## Поля, появившиеся из проверки модели

Четыре поля добавлены не по проекту, а по результату прогона (`testset/PROBE_LOG.md`):
модель знала эти вещи и писала их в свободный текст, потому что полей не было.

| Поле | Почему |
|---|---|
| `panels[].kind` | платёжное табло оператора модель принимала за табличку |
| `main_sign.background_color` | у панелей цвет извлекался, у основного знака — нет |
| `main_sign.form` | зональный знак читается как обычный, но тип у него другой |
| `legibility` | наклейки и обрезка нужны формуле уверенности, а проза в неё не входит |

## Поля, которым код не верит

`boundaries.certain` и `model_confidence` — **самооценка модели**. Хранятся ради замера
на этапе 5 и не являются основанием ни для одного решения: на снимке `013` модель слила
две таблички в одну, сообщив о полной уверенности.

Отдельно `panel_count` намеренно дублирует длину `panels`: расхождение между ними —
независимый сигнал потери границы, и получить его из самого списка нельзя.

## Чего в схеме нет намеренно

- **типа земли** — владелец не может ввести правило против закона, знак означает
  то же самое;
- **класса транспорта по умолчанию** — одинокий `P` круг не сужает, и подставлять
  «легковой автомобиль» нельзя. Поле `vehicle_class` появляется, только когда знак
  действительно сужает;
- **вывода о пользователе** — `eligibility` называет, кому отведены места, и никогда
  не отвечает на вопрос, относится ли к ним читатель.

## Проверка

Валидацию делает свой код — `web/src/lib/schema.ts`: тащить в страницу библиотеку ради
одной проверки дороже, чем написать её. Чтобы проверка не сверялась сама с собой, тесты
судят её независимым валидатором `ajv` на нарочно поломанных разборах. `ajv` — только
для разработки, в собранную страницу он не попадает.

Все эталоны из `testset/expected/` обязаны проходить валидацию. Они же — единственный
источник эталонной разметки: раньше те же данные лежали ещё и в `schema/examples/`,
и две копии одного и того же неизбежно разошлись бы.
